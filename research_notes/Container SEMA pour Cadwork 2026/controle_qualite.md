## 1. Native cadwork checks (2025/2026): what exists and where in the UI

### Takeaway
cadwork 3D has a long-standing native **collision check** ("Contrôle de collision" (FR) / "Kollisionskontrolle" (DE), shortcut Ctrl+K in older manuals, applied to active elements). It also has **production/part-list position-number checks**, an automatic collision cleanup when the Element module calculates walls, a **"No Clash Control" (NCC) plugin** that finds missing contacts, machine-data calculation with error output, and IFC/BCF tooling (BIM Management Tool, BCF Manager). I found no single integrated "pre-production checker" that combines model, shop-drawing and list/order checks, so a custom add-on fills a real gap. Most UI paths below come from older manuals or marketing pages and have to be checked in the 2026 UI.

### Cited Findings
- **Vendor claim (FR, cadwork Amérique du Nord, 3D module):** the 3D module checks the model for duplicate parts and component collisions, and checks that existing evaluations still match the current geometry. Typical errors it is said to catch: "un élément positionné sur un autre, une collision, un tenon mal orienté, un boulon trop court". Based on a search summary; the page was not fetched directly. — [cadwork.ca/fr/modules/3d](https://cadwork.ca/fr/modules/3d/)
- **Vendor claim (DE, cadwork Swiss):** "automatische Kontrollen prüfen die Konstruktion auf Bauteilkollisionen und vergleichen bereits erzeugte Listen, Maschinendaten und Pläne mit der aktuellen Geometrie". In other words, cadwork itself presents list, machine-data and plan consistency against the geometry as a built-in check category. From a search summary. — [cadwork.swiss – cadwork 3D Holzbau](https://cadwork.swiss/module/cadwork-3d-holzbau/)
- **Attribute-filtered collision/contact check:** "depending on attribute of your choosing, perhaps material, you can check which elements collide, or which elements are touching" (EN). The FR framing page has the same wording. — [cadwork.ca – Passive construction](https://cadwork.ca/en/solutions/passive/); [cadwork.ca/fr – Construction à ossature](https://cadwork.ca/fr/solutions/construction-%C3%A0-ossature/)
- **French UI name "Contrôle de collision":** a cadwork training video is titled "Vidéo de la semaine – S19 – 2021 – Contrôle de collision". The basic training level 1 has an exercise "Contrôle collision" (exercise 4-13 per the search summary). These are 2021 materials (older). — [Vimeo cadwork – Contrôle de collision (2021)](https://vimeopro.com/cadwork/video-de-la-semaine/video/605445671); [cadwork – Formation de base niveau 1](https://vimeopro.com/cadwork/cadwork-formation-de-base-niveau-1-maison-de-vacances/video/400897786)
- **German name and shortcut (OLD, v16/v19, ca. 2009–2012):** the "Kollisionskontrolle" function is in the 3D manual v19 with shortcut **Ctrl+K**. The v16 shortcut list has "Kollisionskontrolle für aktive Elemente", so the check runs on the *active* elements. — [Manual 3D v19 (2012)](https://ftp.cadwork.ch/cadwork.ftp/manuals/deutsch/holzbau/version19/Manual_3d_v19.pdf); [Shortcuts 3D v16](https://ftp.cadwork.ch/CADWORK.FTP/MANUALS/deutsch/holzbau/version16/Shortcuts/Shortcuts_3D_v16_de.pdf)
- **Collision check tied to cutting (OLD, v19 machine manual):** under the cut/weld options, the collision check detects intersections that were not yet executed, i.e. parts that still collide because a cut was never applied. A separate **position-number check** compares newly calculated production numbers with the existing ones. — [Manual Maschinenausgabe v19 (2012)](https://ftp.cadwork.ch/cadwork.ftp/manuals/deutsch/holzbau/version19/Manual_Maschinenabbund_19.pdf)
- **Element module (walls/floors):** a collision check runs during element calculation. If an element lies entirely inside another, it is deleted. The check can be switched off, for example for insulation that is cut later in 3D. From a search summary of a KB news page. — [cadwork KB – News Element module](https://kb.cadwork.ch/en/news/manual/1789/elementbau)
- **"No Clash Control" (NCC) plugin:** described as "l'inverse du contrôle collision". It detects parts that are *not* in contact, based on distance and element-type conditions, and was reportedly offered free to all clients (LinkedIn post by a cadwork FR sales/training contact, ~2022; older, status in 2026 unverified). — [LinkedIn – A. Bouilleaux on NCC](https://fr.linkedin.com/posts/aurelienbouilleaux_g%C3%A9nial-ce-plugin-cest-linverse-du-contr%C3%B4le-activity-6982972710779764736-rUWr)
- **Machine export errors (OLD, Hundegger K1/K2 manual v11, 2002):** if errors occur during conversion, a `*.err` error file is created and can be read with "Show Error File". Warnings and errors also appear in the message window. Elements that cannot be processed by the Hundegger machine should be hidden before export. — [cadwork K1/K2 manual v11](http://ftp.cadwork.ch/CADWORK.FTP/MANUALS/english/Timber/old/version11/man_k2_11_en.pdf)
- **Hundegger strict data checking (cadwork V30 / SP2024 news, per search summary):** Hundegger checks received BVX data strictly for conformity, and non-conforming files must be re-exported with a current cadwork version. The "Activate attribute → Machine data" function activates all parts that already have calculated machine data, and that data can be outdated (so recalculate before export). — [cadwork News Version 30 (SP2024) PDF](https://filehost.cadwork.ca/doc_website/en_News_Version_30_(SP2024).pdf) *(attribution from search summary; PDF not opened)*
- **BIM tooling:** the cadwork BIM-Manager/IFC module covers IFC2x3/IFC4 import/export, multi-IFC management, the **BIM Management Tool (BMT)**, IFC attribute mapping and **BCF** support. — [cadwork.de – BIM-Manager / IFC](https://cadwork.de/en/solutions/bim-manager-ifc/); [cadwork.ca – BIM Management Tool](https://cadwork.ca/en/modules/bim-management-tool/)
- **BCF Manager:** opened from the BIM_Management tool or from the Window menu. Listed BCF use cases include identifying clash-detection issues between discipline models. From a search summary. — [cadwork-bim docs – BCF](https://cadwork-bim.readthedocs.io/de/latest/en/4.BCF/bcf/)
- **cadwork 2026 platform facts relevant to an add-on:** "With Version 2026, various Plugins are installed by default… adapted to PyQT6". PyQt5 uses must be ported to PyQt6, Lua support was dropped, and the Python interpreter is now **3.14**. — [cadwork KB – News 2026 Plugins](https://kb.cadwork.ch/en/news/manual/1877/plugins). This is corroborated by the official stub package, which requires Python `>= 3.14` for v33. — [cwapi3dpython pyproject.toml](https://github.com/cwapi3d/cwapi3dpython/blob/main/pyproject.toml)
- **Practice example:** a Swiss planning office reports finding and fixing collisions and inconsistencies with the "Kollisionskontrolle" after importing an architect model. — [Schwyter Bauplanung](https://schwyter-bauplanung.ch/alle-anzeigen/holzbauplanung)

### Inferences
- The native check menu (in recent versions probably under an "Analyse"/"Contrôle"-type menu, with Ctrl+K kept as shortcut) covers **geometry** (collisions, plus duplicates according to marketing) and **numbering consistency**. It does not cover company rules (mandatory attributes, section catalogue, stock length, connector presence at joints). Those company-specific rules are the main value a custom tool adds.
- The fact that the native collision check works on active elements suggests the add-on should also offer "check active selection" vs "check whole model" modes.
- The Element-module auto-delete of fully contained elements is a silent model change. The add-on should report "contained" cases rather than delete them.

### Gaps
- I found no 2025/2026 cadwork help page giving the **exact current French menu path** for "Contrôle de collision", the duplicate check, or "Contrôle des numéros de position". The pages are on docs.cadwork.com / kb.cadwork.ch (not reachable here). They should be checked in the cadwork 2026 FR UI or help.
- I could not confirm a native **"processing not machinable"** report UI in 2025/2026. The only evidence is old (`.err` file, v11) or indirect (Hundegger strict BVX checking).
- I could not confirm whether NCC is still distributed in 2026, or whether it is among the "plugins installed by default" (the KB snippet only named "Wall Corner 9").
- I found no source that describes a native "shop drawing completeness" check (fiches de taille). The marketing claim "compare plans with current geometry" is the closest match.

## 2. Third-party checkers commonly used with cadwork

### Takeaway
For model checks outside cadwork, the documented route is **IFC export → rule-based checker (Solibri Office) or free IFC viewers**, with issues sent back through **BCF** (cadwork has a BCF Manager and the API has `bim_controller.import_bcf` / `export_bcf`). I found no cadwork-specific third-party "pre-production checker" product. The add-on idea is therefore not duplicating a market product.

### Cited Findings
- cadwork's KB recommends checking the IFC export translator settings before handing a model on. For checking, it recommends **Solibri Office** (rule-based check) or various free IFC viewers (visual check). From a search summary. — [cadwork KB holzbau PDF 1090](https://kb.cadwork.ch/holzbau/pdf/en/1090)
- BIMcollab lists Solibri as an IFC tool (import, merge, validate, check, export) linked to BCF. — [BIMcollab integrations](https://helpcenter.bimcollab.com/portal/en/kb/articles/bimcollab-integrations)
- A review site says BIMcollab's clash detection is fine for basic use but cannot manage clash status/assignments individually (opinion, third-party). — [SelectHub – Solibri vs BIMcollab](https://selecthub.com/building-information-modeling-software/solibri-vs-bimcollab)
- cadwork's **BIMteam** (cloud/Windows viewer) has had six versions since V30 SP2024, with scene export from the 2025 version. — [cadwork KB – News BIMteam](https://kb.cadwork.ch/en/news/manual/1823/bimteam)
- API hooks for this route exist in both 2025 and 2026: `bim_controller.export_ifc4_silently(element_id_list, file_path)`, `export_ifc4_silently_with_options(...)`, `export_ifc2x3_silently(...)`, `import_bcf(file_path)`, `export_bcf(file_path)`, `get_ifc_guid`, `get_ifc_base64_guid`, `get_element_id_from_base64_ifc_guid`. New in 2026 (v33): `export_ifc4`, `export_ifc2x3`, `load_ifc_export_settings`. — [cwapi3d bim_controller stub (main)](https://github.com/cwapi3d/cwapi3dpython/blob/main/src/bim_controller/__init__.pyi); [release notes 33.378.0](https://github.com/cwapi3d/cwapi3dpython/blob/main/docs/release_notes.md)
- An open-source MCP server + cadwork plugin for cadwork 2026 exists (Python 3.14). It is not a checker, but it is a reference for AI-driven tooling on cwapi3d. — [GitHub sebastiankoukoui/open-mcp-cad](https://github.com/sebastiankoukoui/open-mcp-cad)

### Inferences
- `get_element_id_from_base64_ifc_guid` makes a round trip possible: Solibri/BIMcollab issue (IFC GUID) → cadwork element ID → `visualization_controller.set_active`. The add-on could import a checker's issue list (BCF or CSV of GUIDs) and highlight the elements in cadwork.
- For a charpente SME, Solibri is likely overkill for internal pre-production checks. A cadwork-side Python checker covers attribute, list and machine rules that IFC checkers cannot see (BTL processings, production numbers, cadwork list settings).

### Gaps
- "Caddev" tools: I found **no source** for a "Caddev" cadwork checking tool, so I can neither confirm nor deny that it exists.
- No source documented an actual cadwork → Solibri/BIMcollab clash workflow for timber, or the quality of BCF round trips from cadwork.
- design2machine/BTLx validators (e.g. BTLx viewers used to validate files before machines) were not researched in depth. Only the BTL interface spec appeared ([BTL v10.4 spec](https://www.design2machine.com/btl/btl_v104.pdf)).

## 3. Which API functions support each check (exact names from the cwapi3d stubs)

### Takeaway
The cwapi3d API (2025 = v32, 2026 = v33) **directly provides most of the check primitives**: `element_controller.check_element_duplicates`, `get_elements_in_collision`, `check_if_elements_are_in_collision`, `get_elements_in_contact`, `filter_elements`/`map_elements`, `list_controller.check_position_numbers_production_list` / `check_position_numbers_part_list`, geometry getters (`get_length`, `get_list_length`, `get_volume`, …), attribute getters, machine-data calculation and per-element BTL/Hundegger processing lists, and BIM building/storey getters. cadwork 2026 adds `geometry_controller.get_element_collision_type`, which classifies collisions as contained / coincident / interlocking / touching. Missing joints, connector counts vs lists, and list totals vs purchase orders need **custom logic** built on top of these primitives.

### Inferences — proposed prioritized check catalog (built on the confirmed functions above)
Priority: **P1 = blocking before sending to the workshop or suppliers**, P2 = warning, P3 = info. "ids" = filtered identifiable elements, excluding `is_auxiliary`, `is_processing`, `is_drilling`, `is_opening`, `is_node`, `is_surface`, `is_line`, export solids and containers (tunable).

- Implementation notes (inference): use `map_elements` / `filter_elements` for attribute checks, which are likely much faster than per-element getter loops. Pre-filter collisions with bounding boxes (from `get_p1/p2/p3` and dimensions) before calling `check_if_elements_are_in_collision`, because pair checks are O(n²). Since build 298's exact API level is unknown, guard 2026-only functions with `hasattr(geometry_controller, "get_element_collision_type")` and log `get_3d_version()` and `get_3d_build()` in every report.
- The check catalogue is best kept as a **registry of check objects** (id, label FR, priority, scope, `run(ids) -> list[Issue]`). This mirrors the extensible action-registry pattern the company already uses and lets checks be added without touching the core.

### Gaps
- **Build 298 vs API level:** the user's "cadwork 3D 2026 build 298" might mean cwapi minor version 298. If the cwapi minor version tracks the cadwork build (not confirmed, but PyPI has a `32.298.0`), then functions added in 33.378+ (e.g. `get_element_collision_type`, `get_standard_element_guid_from_name`, `get_elements_for_storey`?) **may be missing in build 298**. I could not find when `get_elements_for_storey` was added (it appears in v33 stubs, not in v32). Verify on the machine with `utility_controller.get_3d_build()` and `hasattr`.
- The **behaviour of `check_element_duplicates`** is undocumented: it is unclear whether it returns all members or only the extra copies, and which tolerance applies. The same goes for `get_elements_in_collision` (does touching count? performance on large models?). Both need testing on a sample model.
- No API function exposes a **"processing not machinable / outside machine range" status** per processing. Only the processing lists, codes and parameter sets are exposed, so the machine error file content is not reachable via API (unverified).
- No API was found to **read back the content of an exported list** (production/part list) or the cadwork list totals. The tool would have to parse the exported file (format depends on list settings), or recompute totals itself.
- docs.cadwork.com pages were not readable here, so the online docstrings were not compared with the repo stubs (they are generated from the same repo, which makes this low risk).

## 4. How to present results: report window, highlighting, checklist export, blocking export

### Takeaway
Highlighting is fully supported: `visualization_controller.set_active`, `set_color`, `set_color_without_material`, `set_element_transparency`, `set_visible/invisible`, `zoom_active_elements`, `refresh`, plus status-bar messages and progress bars (`utility_controller.print_error`, `print_message`, `show/update/hide_progress_bar`). Rich report windows have to be built in **PyQt6** (bundled with cadwork 2026) or tkinter. No API to **intercept cadwork's native export** was found, so "blocking export" means the add-on owns the export buttons and calls the export functions only after a clean check.

### Inferences
- Recommended UX: a dockable PyQt6 report (table: severity, check, element count, message). Row click → `set_inactive(all)`, `set_active(ids)`, `zoom_active_elements()`. An "Isoler" button sets non-faulty elements to transparency/invisible. A "Colorer" button uses `set_color_without_material` after saving `get_color`, with a "Restaurer" button. Prefer activation and transparency to recoloring, because colour is often meaningful in a charpente model (and in shop drawings).
- Also write the faulty IDs into a user attribute (e.g. "QC_STATUS" via `attribute_controller.set_user_attribute`). The user can then filter natively with cadwork's attribute tools after the dialog is closed (inference; `set_user_attribute` confirmed in the stubs).
- Export the checklist as CSV/XLSX/PDF with project, `get_3d_file_name()`, `get_3d_version()`/`get_3d_build()`, date, user, and the counts per check. Archive it next to the BTL/list files to keep a traceable "bon pour fabrication".
- "Blocking export": provide a "Contrôler puis exporter" command that runs all P1 checks and calls the silent export functions only on success, or on an explicit override recorded in the report (`get_user_bool`). Native cadwork export menus stay usable, so this is procedural, not a hard lock.
- The `event_type` enum hints that 2026 plugins might react to events (e.g. on_geometry → invalidate check results). No registration function was confirmed (see gaps).

### Gaps
- No confirmed API to **register event callbacks** or to **hook/disable native export commands**. Only the `event_type` enum was seen in the release notes.
- No confirmed API to **create BCF topics/issues programmatically** (only `export_bcf`/`import_bcf` of the whole file). Pushing check results as BCF issues is unverified.
- Whether `set_color` modifies the element's material assignment in 2026 is unclear. The existence of `set_color_without_material` suggests it does, so test before use.

## 5. Good practices from timber-construction QA (pre-production checklists) applicable here

### Takeaway
Industry practice is a **formal gate before release**: an independent line-by-line review of shop drawings, a cross-check of cut lists and CNC reports against the drawings, coordinated openings and penetrations, defined tolerances, and transport/lifting feasibility. An automated checker fits the "gate" step, but it does not replace a human sign-off. Hundegger's strict data-conformity checking also argues for exporting with the current cadwork version and recalculating machine data right before export.

### Cited Findings
- The Timber Frame Engineering Council publishes a **Timber Frame Shop Drawing Checklist** (revised 2012, D. Hourdequin, D. Sheidler). It covers the cover sheet, isometrics, general notes (incl. TFEC master general notes) and project specifics (older; full content not retrieved). — [TFEC checklist PDF](https://www.carolinatimberworks.com/wp-content/uploads/2020/08/Timber-Frame-Shop-Drawing-Checklist.pdf); [TFEC publications](https://old.tfguild.org/timber-frame-engineering-council/timber-frame-shop-drawings)
- Mistake-proofing practice (cabinetry, transferable): the engineering manager checks all drawings for accuracy before they leave the office, and the shop foreman double-checks the cut list / CNC part reports against the drawings. — [WOODWEB – Mistake-Proofing Cabinet Jobs](https://woodweb.com/knowledge_base/MistakeProofing_Cabinet_Jobs.html)
- DfMA for timber: settle before fabrication whether openings/penetrations are coordinated and whether elements can be transported and lifted. Research points to dedicated model validation before fabrication for mass timber. — [Construsoft – DfMA in timber](https://insights.construsoft.com/blog/why-dfma-is-becoming-more-relevant-in-timber-construction); [Construsoft – key challenges in timber projects](https://insights.construsoft.com/blog/key-challenges-in-timber-projects-and-why-many-teams-feel-unprepared)
- The shop drawing is "the last point where the design can be checked against fabrication reality", and filing it without a line-by-line review "is not a review" (SIP manufacturer, opinion). — [Premier Building Systems](https://sips.premierbuildingsystems.com/blog/why-the-shop-drawing-is-the-most-important-document-on-a-sip-project)
- Prefabricated timber tolerances should be quantified and communicated from design to site (CWC, 2026). — [CWC – Understanding Tolerances (2026)](https://cwc.ca/wp-content/uploads/2026/03/CWC_Solutions_UnderstandingTolerances_Mar3026.pdf)
- cadwork's own message: recalculate machine data (existing data can be outdated), and re-export with a current version because Hundegger checks BVX conformity strictly. — [cadwork News V30 SP2024](https://filehost.cadwork.ca/doc_website/en_News_Version_30_(SP2024).pdf) *(via search summary)*

### Inferences
- Translate into a 3-stage gate for the add-on: (1) **Modèle** (M1–M6, M10, M13, M15), (2) **Fabrication** (M7–M9, M14, M19: numbering, machine data, shop-drawing coverage), (3) **Achats** (M11, M12, M16: hardware BOM, material totals vs PO). Each stage produces a signed checklist ("contrôlé par / date / build cadwork").
- Store company rules (section catalogue, stock lengths per material, mandatory attributes, collision whitelist, max weight) in a versioned JSON/CSV next to the plugin and synced via Git between machines, so the checks are reproducible and auditable.
- A SEMA → cadwork migration is a high-risk period. Run the checker on SEMA-era reference projects re-modelled in cadwork to calibrate thresholds and reduce false positives before making P1 checks blocking.

### Gaps
- I found no timber-specific (charpente FR) published pre-CNC checklist with item-level content, e.g. from FCBA, CODIFAB or Les Compagnons. The full TFEC checklist text was not retrieved.
- No source quantified error rates or savings from automated checking in cadwork workflows.
